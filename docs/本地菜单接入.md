# 本地菜单快照

支持把 `menus.json` 与 `shops.json` 接入当前 MySQL 或 SQLite。导入器只读取数据，不使用压缩包中的代码。v0.3.0 公开源码和桌面包附带经过清洗的 `data/catalog_meituan.json`，新安装会启用它；原始压缩包、原始采集文件、个人数据库和本机模型设置不发布。后续自行导入的文件默认写入被 Git 忽略的 `data/local/`。

## 转换并启用

在项目根目录运行，数据库连接沿用本机 `.env`：

```powershell
.venv\Scripts\python.exe scripts/import_meituan_catalog.py --archive "饭点搭子_美团数据接入_20261107.zip" --activate
```

也支持 `--raw-dir 数据目录`，目录中应有 `menus.json` 和 `shops.json`。去掉 `--activate` 只生成文件；默认输出 `data/local/catalog_meituan.json`。导入在事务内完成，只更新餐食目录和当前来源，保留账号、标签、段落记忆、聊天和用餐记录。重复导入相同内容不会重复插入。

更新源码后重新构建前端、重启服务，再刷新网页。目录更新会使旧推荐卡失效；历史聊天和用餐记录继续保留原内容，新一轮使用当前目录。

切回演示目录：

```powershell
.venv\Scripts\python.exe scripts/import_meituan_catalog.py --use-demo
```

切换选择会保留到下次启动。如设置了 `FANDIAN_CATALOG` 自动导入路径，应先清除该设置，否则下次启动会再次启用该快照。也可设 `FANDIAN_CATALOG=demo` 强制使用虚构演示目录。

## 桌面使用

v0.3.0 已附带本次清洗快照，无需手动导入（原公开 v0.2.0 不支持）。更换目录时，把转换后的文件命名为 `catalog.json`，放在 `FandianDazi.exe` 旁边，重新启动即可。也可放在 `%LOCALAPPDATA%\FandianDazi\catalog.json`，后者优先。应用会增量导入本机数据库，已有记忆保留；文件移除后已导入的目录仍保留在数据库中。

源码调试桌面端会优先发现项目中的 `data/local/catalog_meituan.json`。`FANDIAN_CATALOG` 可显式指定路径，优先于上述两处。公共构建仅内置版本控制中的 `data/catalog_meituan.json`；打包脚本默认拒绝把额外的 `catalog.json` 混入发行包，只有本机演示打包才显式使用 `--include-local-catalog`。

## 这次数据与筛选口径

原始记录：39 家有菜单商户、616 条菜单项，商户列表共 156 家；菜单采集时间是 **2026-11-02 15:01:48**，参考区域为复旦大学北苑学生生活园区。压缩包文件名日期不等于采集日期。

转换得到 132 条来自 17 家商户的正餐记录。其中 90 条所有规格在采集时库存为零，保留记录但暂不参加推荐；42 条进入后续预算、渠道、时间和食材线索筛选。去除重复 39 条、无效价格 9 条、饮料 337 条、明显配菜/加料/无法可靠识别为正餐的 99 条。基于名称的正餐识别可能有漏收，未来应结合人工审核与商户品类数据。

- 价格按采集时有正库存规格的最低价格；没有可确认的正库存规格时保留原起价，不能当作实时可购买价格。
- 缺失包装费不补成 0；带“满”“约”“起”的配送报价不当作无条件配送费。卡片标“已知费用起”，可能不满足最终预算。
- 配料只保留菜名线索，不从“肉”推断猪肉、不从“包”推断包子；没有某食材线索不等于不含该食材。
- 没有辣味关键词不等于不辣；没有营业时间不虚构全天营业。全部采集候选都需向商户确认口味、忌口、库存和营业状态。
- 用餐时间按历史送达报价加取餐、用餐、返回和缓冲假设估算，既不是实时送达承诺，也不是实际路径计算。无法估算时间的条目不参与有明确截止时间的推荐。
- 真实采集目录启用后不混入虚构食堂；因此只选“食堂”时可能没有候选。
- 不下载或展示平台商品图片，保留应用自有插画。本版仅发布已确认可公开的清洗目录；不附带原始采集压缩包。

当前仍是离线快照接入，没有连接美团实时 API、下单、支付、库存更新或价格刷新。
