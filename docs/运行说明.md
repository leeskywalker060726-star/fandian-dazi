# 饭点搭子运行说明

## 启动原型

当前 Windows 工作目录是 `H:\黑客松`，前后端依赖已安装，前端已经构建。

在项目目录运行：

```powershell
.\scripts\start.ps1
```

打开 http://127.0.0.1:8000 。选择“先体验一下，不用注册”，完成偏好设置后进入原型；也可以创建用户名密码账号。开发环境 API 文档在 http://127.0.0.1:8000/docs 。

在新电脑安装依赖并构建：

```powershell
.\scripts\setup.ps1
.\scripts\start.ps1
```

需要 Python 3.13 与 Node 24。若 PowerShell 本机策略限制运行脚本，可以在终端逐条执行脚本里的命令，无需修改系统安全策略。

## 配置说明

把 `.env.example` 复制为 `.env` 后填写配置。`.env` 已加入 Git 和 Docker 构建忽略规则，不要提交密钥。现有 MySQL 密码和模型密钥均保留在本机，运行脚本不打印它们。

| 配置 | 含义 |
| --- | --- |
| `APP_MODE=demo` | 本地开发与比赛演示；允许本地 HTTP 登录 Cookie |
| `APP_MODE=production` | HTTPS 环境使用，登录 Cookie 启用 Secure；仍需另行完成生产加固 |
| `USE_MYSQL=true` | 使用下面的 MySQL 连接信息 |
| `MYSQL_HOST`、`MYSQL_PORT` | MySQL 地址和端口；本机通常为 127.0.0.1 和 3306 |
| `MYSQL_USER`、`MYSQL_PASSWORD` | 数据库用户名与密码，密码不需要 URL 编码 |
| `MYSQL_DATABASE` | 应用数据库，默认 fandian；初始化只创建这一数据库和自身表 |
| `LLM_BASE_URL` | 兼容 Chat Completions 的根地址；DeepSeek 可填写 https://api.deepseek.com，不要附加 /chat/completions |
| `LLM_MODEL`、`LLM_API_KEY` | 实际可用模型名和密钥 |
| `MCP_ENABLED=true` | 通过本地 MCP 子进程查询演示餐食目录 |

未配置模型时使用规则演示；模型故障时显示降级提示。DeepSeek 适配器在结构化工具调用阶段关闭思考模式，因为该服务的思考模式不支持强制指定工具，见 [官方接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)。这不会更换用户填写的模型或密钥。

将 `USE_MYSQL=false` 可切换 SQLite 本地演示数据库 `.runtime/fandian.db`。切换数据库不会自动迁移账号和记录。

## 开发命令

```powershell
# 后端开发服务
.\.venv\Scripts\python.exe -m uvicorn apps.api.main:app --host 127.0.0.1 --port 8000 --reload

# 前端开发服务，另开一个终端
node .runtime/package/bin/npm-cli.js run dev

# 前端类型检查和构建
node .runtime/package/bin/npm-cli.js run build

# 独立测试库的集成测试，不操作配置中的 MySQL
.\.venv\Scripts\python.exe -m pytest -q

# 验证正在运行的本地服务，会创建并清理一个临时访客账号
.\.venv\Scripts\python.exe scripts/live_smoke.py

# 真实模型多轮对话、跨会话段落记忆和导出验证
.\.venv\Scripts\python.exe scripts/conversation_smoke.py
```

如果电脑已有 npm，可以将 `node .runtime/package/bin/npm-cli.js` 换成 `npm`。后端使用一个进程运行，用户级写入锁基于该前提；当前不要增加多个 worker。

## 比赛演示路径

1. 访客进入，选择清淡、不吃香菜、25 元预算。
2. 点击“今天想省一点”，查看主推荐和两个备选。
3. 点击“换一家”，确认预算和忌口保留。
4. 输入“这周每顿最多15，以后别推奶茶”，查看记忆更新提示。
5. 打开饮食记忆，查看临时预算、长期偏好和来源，也可导出 Skill ZIP。
6. 新开一餐，确认预算继承；选择餐食后在用餐记录填写反馈和实际花费。
7. 将演示时间改为 23:00，再推荐一次，查看关门过滤。

所有餐食、价格、路线和天气都是明确标注的演示数据。餐食选择不会下单。过敏与医疗饮食请求会提示缺少核验数据，不输出安全保证。

## 当前实现边界

已实现注册登录、隔离访客、标签设置、多轮推荐、长期及本周偏好、编辑忘记、记忆开关与资料导出、餐食选择、实际用餐与支出反馈，以及 MySQL、MCP 和模型工具调用适配。

聊天先识别闲聊、追问、记忆表达和选餐请求，再由模型结合最近对话与有效记忆生成回复。只有明确选餐和调整请求才调用目录并展示餐食卡；追问使用上一轮候选。价格、时长通过目录字段引用填入，数字或引用校验不通过时尝试修正一次，仍失败才显示备用回复。未配置模型时使用简短规则回复。

饮食记忆同时包含结构化偏好、自然语言概览和本人背景段落。说“帮我记住：……”可直接保存段落；普通聊天中提到的生活背景先产生待确认建议，可在记忆页保存，也可在只有一条建议时说“帮我记住刚才这段吧”。段落可编辑、忘记，支持长期、本周或七天有效期；原文保存，不推测补写个人经历。Skill ZIP 同时包含 profile.json、profile.md 与 about-me.md。背景用于理解和解释，不自动覆盖预算、忌口等筛选条件。

尚未实现：RAG、真实天气与课表、主动提醒、记忆变更撤销、跨进程并发控制、完整运营后台。初始表通过 SQLAlchemy 创建，后续涉及已有表结构修改时需增加迁移；不要把 `create_all` 当作数据迁移机制。

首版 MCP 按轮创建短生命周期子进程，工具只读；本地使用当前数据库账号，尚未配置独立的目录只读账号。公开部署前应完成数据库最小权限、登录限流、HTTPS、备份与数据留存配置。应用暂未公开部署。

## Docker 部署配置

仓库提供 Dockerfile 和 Compose，前端构建后由 FastAPI 同源提供，因此运行时只需 app 和 mysql 两个容器。先在 `.env` 设置 `DOCKER_MYSQL_ROOT_PASSWORD`，再执行 `docker compose up --build`。

容器中的应用使用专属 fandian 数据库用户；MySQL 端口不对宿主机暴露，应用端口绑定本机 8000。当前开发机未检测到 Docker，因此容器构建与运行尚未实测。

## 自然聊天与段落记忆演示

1. 输入“今天有点累，只想聊两句”，检查没有自动推荐餐食。
2. 输入“最近实验很多，我经常很晚才吃饭，排长队的时候就更烦了”。
3. 在饮食记忆页确认这段建议，或直接说“帮我记住刚才这段吧”。
4. 新开会话，问“你还记得我最近为什么不想排队吗”，验证背景被使用。
5. 再说“清淡一点，帮我选午饭”，此时才显示推荐卡；接着问“为什么推荐第一个”。
6. 在记忆页编辑或忘记背景，再聊时不会从旧消息恢复原段落。

模型只接收当前用户最近十条有效消息及最多八段已确认背景；记忆变更、关闭或到期会使旧版本对话退出模型上下文。聊天记录仍可见，这是一种保守的遗忘隔离策略。当前 SSE 提供处理中状态与最终完整回复，不逐字假装模型流式输出。
